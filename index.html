Scene 1 · The message

Alex sends a photo.

A photo can contain lots of data. For our story, imagine it travelling in smaller pieces called packets.

🧑‍💻🖼️📨

“Send it to Sam!”

Alex: “Here's my photo!”

Applications send data through a network connection.

📦📦📦

Three little packets

TCP Hero: “I'll keep track!”

TCP sequence numbers identify positions in a byte stream, helping data be put back in order.

Scene 2 · The mix-up

Oh no — P2 is missing!

Networks can delay or lose data. TCP uses acknowledgements and recovery mechanisms to deal with missing pieces.

💻➡️🖥️

Sam gets a piece

Sam: “I received some data!”

The receiver keeps track of the data it has received.

📦💥😮

Where did it go?

TCP Hero: “Let's check what's missing!”

ACKs and timers help TCP determine when data needs to be sent again.

Scene 3 · The rescue

TCP sends the missing data again.

When TCP detects loss, it can retransmit the missing data. The receiver then gets an ordered byte stream.

🖥️💬📨

ACK! Message received

Sam: “Got data up to here!”

An acknowledgement tells the sender about receipt progress.

🦸📦🔁📦

Delivery restored

TCP Hero: “P2 is on its way!”

TCP's reliability comes from tracking data, acknowledgements, and recovery—not from making every network perfect.

Remember: This is a simplified story. TCP delivers an ordered byte stream; packet boundaries are not the same as application message boundaries.
